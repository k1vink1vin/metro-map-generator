# 大台北與桃園路網圖印刷複驗

用專案根目錄的 `TPE_Metro.xlsm` 重現。這版工作簿有 321 筆站碼、270 個圖面站點、15 條路線、21 條路徑與 307 條路網邊。原始站名、座標、轉乘分組、行車順序和配色由工作簿提供。路網包含規劃路線，台鐵與高鐵為工作簿選錄的部分站點。270 個圖面站點都缺英文站名，圖例有標示資料範圍。

## 版式和符號

| 路網版式 | 圖面與驗收重點 |
| --- | --- |
| Geographic | 北向經緯度投影等比例放大，維持座標相對位置，附北箭頭與依投影計算的比例尺。近鄰站點以小錨點和引線分開。 |
| Taipei 45° | 45° 路線，保留相對地理方向，淡水河作為示意地標。 |
| London 45° | 45° 路線，優先辨識中心密集路網及轉乘，採規律站距。 |
| Moscow Ring | 工作簿定義兩個獨立圓心的正圓環，非環路段採 45°。檢查全圖的地理順序與環線的圓心。 |
| Concentric | 同一圓心的圓弧與放射直線。此工作簿以台北車站為中心，網頁可改選任一站。逐走廊調整站距和錨點，保留鄰近區域的相對方位。 |
| Hex 60° | 直線段符合 0°、60°、120° 三軸，非站點折角使用相切圓弧，保留支線、轉乘和分歧順序。 |

每種路網版式各輸出台北、東京、大阪、莫斯科四種站點符號。色框和色塊沿用對應路徑顏色，淡色路線加深色外邊。大阪的色塊依底色使用黑字或白字。莫斯科的轉乘圓環包含各路徑顏色。路線交叉處用斷開表示無轉乘，轉乘點有專用站點符號。精確重合的直線或圓弧分色並排，依圖例可追蹤每條路線。

## 重現

```sh
npm install
npm run build
npm run qa:geometry
npm run qa:workbook
npx playwright install chromium
METRO_PRINT_PDF=1 npm run qa:print
npm run qa:browser
```

CI 使用 Node.js 22 與 Chromium，並以 Noto Sans CJK TC 驗證排版。若系統已安裝 Chromium，可以設定 `CHROMIUM_PATH`。工作簿 QA 同一行程只算一次各版式，並產生以下檔案。CI 以 `tpe-metro-style-qa` 提供下載。

瀏覽器回歸測試使用正式建置，驗證 Excel 空白值與錯誤列號、JSON 驗證失敗時的版式和來源、活頁簿改名後的預設圓心、桌面及手機的站點定位與 SVG 下載。

- `qa-artifacts/*--stations-*.svg` 為 24 張完整圖，沿用網頁實際使用的 SVG 元件和樣式。
- `qa-artifacts/print/*.pdf` 為 24 張單頁校樣，四周留白 10 mm，中文站名字級 4.5 mm。每張的實際尺寸記在印刷 QA 報告。按 PDF 的尺寸原大印製，字級會隨紙張縮放。
- `qa-artifacts/workbook-manifest.json` 包含輸入檔 SHA-256、站名、站碼、路徑順序及配色。
- `qa-artifacts/print-audit.json` 記錄每張圖的頁面尺寸、站名與站牌重疊、站名與路線相交、裁切、站碼、路徑差異及圖面比例尺實測。報告附工作簿、各 SVG 和 PDF 的 SHA-256 以及 Node.js 和 Chromium 版本，CI 另記錄原始碼版本。
- `qa-artifacts/geographic-order.json` 記錄每種版式的東西與南北順序正確率，以及淡水、台北車站、南港展覽館、桃園和板橋的具名方位檢查。每軸比較約 3.6 km 以上的差距，示意版式每軸須達 97%。
- `qa-artifacts/moscow-geography.json` 列出莫斯科版全部顯著方向反轉。`moscow--huilong-taoyuan-detail.svg` 用來複驗迴龍與桃園車站的相對位置。

數值檢查涵蓋路徑與錨點順序、實際 SVG 角度、獨立圓心／共圓心、採樣自交、轉乘與支線，以及印刷圖在瀏覽器中排版後的字框。印刷校樣依工作簿資料繪製。站內正式導引的雙語資料與營運單位審核仍待補齊。

## Gemini 複驗回應

以下比對以 `4af2367` 的工作簿輸出為基準。輸出中的台北、東京、大阪與莫斯科指站牌符號，中文字與英文欄位都沿用工作簿。

| 報告的議題 | 核對與調整 |
| --- | --- |
| 同心圓徑向折返 | 台北車站中心的基準圖中，站序本身有 20 次徑向方向變化，含穿越中心及環線。另有兩處站間繞行。新選線評分減少圓弧與放射線間的直角接合，並縮短兩處仍需保留的繞行。保留共圓心幾何與車站順序，採樣檢查自交與近 180° 折返。 |
| 標題、圖例、共線 | 主標題按圖幅短邊放大。圖例最多放大 1.5 倍，先測試左上留白能否容納圖例，並逐一避開路線、站名、站牌與引線。並行色帶加寬並增加各色間隔。 |
| 莫斯科雙環 | `RING_1` 有 42 站，`RING_2` 有 36 站，兩個環的站序都未列入台北車站。以環線底色區分主次，保留兩環的半徑、站距與地理驗收。 |
| 六角轉角 | 只在沒有站點錨在角上的折點加相切圓弧。直線段仍符合 0°、60°、120°，站點維持在原位。 |
| 地理圖及長直線 | 圖面是站點座標投影與站間直連。工作簿中最長的相鄰站段是高鐵板橋至高鐵桃園站，兩站直線距離約 25.2 公里。新增線形控制點需要可追溯的軌道座標。 |

額外報告包括 `concentric-routing.json` 的徑向變化與折點，以及 `concentric-centres.json` 的台北車站、忠孝復興、板橋中心偏差。Chromium 檢查涵蓋實際主線、外框、並行色帶、圖例和引線。核心視覺改善以圖面實際排版與方位檢查為準。

### v2 報告複驗

- 同心圓版在 `57b8f82` 已將圓弧與放射線的直角接合從 162 處減至 151 處，兩處站間繞行的累計額外徑向距離從 64 降至 48 圖面單位。仍可見直角過渡。環線、切線與穿越中心的走廊依實際站序進出半徑層，單靠 BFS 的離心單調條件無法處理這些走廊；螺線也會超出共圓心圓弧和放射直線的版式規則。圖例現已指明淺色虛線是同心圓輔助線。
- 莫斯科版在 `57b8f82` 比較 54,631 組顯著軸向關係，反轉數為零。以同一工作簿和布局器試跑環半徑比 0.60，出現 129 筆反轉與一條萬大樹林線自交。0.80 和 0.82 分別出現 86 和 120 筆反轉。0.83 在試跑中維持零反轉，但莫斯科站牌樣式出現觀潮廣場站名與站點符號相碰。採用現有雙環尺寸及底色主次。
- 地理版的四種站牌輸出都用 Chromium 檢查 270 個實際文字框。現行引線按站牌和文字的圖面空間配置，縮放後仍適用。新增比例尺及站間直連說明，地理座標維持工作簿原值。
- 台北、倫敦、六角版沿用已通過的站距和路徑，並逐軸量測跨區順序。六角圓角依相鄰直線可用長度與折角求相切圓弧，固定倍率可能侵入鄰近站點或支線。
